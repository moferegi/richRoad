# 英语学习模块 (English Learning) 开发规范

## 1. 核心隔离原则（保护现有试衣业务）
- **实体隔离**：严禁将英语单词、视频集数等业务数据硬塞入原有的 `goods` 或 `sku` 表中导致结构臃肿。本模块必须创建独立表，如 `english_category`, `english_word`, `video_series`, `video_episode`。
- **体系复用**：可以复用原有的用户体系（User）、积分流水（PointRecord）以及支付基础能力，但模块自身的业务逻辑必须放在独立的 Plugin 或独立的 API/Service 分组（如 `api/v1/english`）中。

## 2. 权限与商业化机制（Unified Auth & Billing）
- **权限模板统一**：继续遵守项目中已建立的后台权限拦截与鉴权体系，不可绕过中间件。
- **全局时长/局部会员解耦**：
  - **时长消耗优先**：实现“注册免费时长”的判定时，应使用挂机防作弊机制（如前端 30 秒轮询上报心跳包扣除 `free_minutes`）。
  - **鉴权优先级**：`免费时长有余额 -> 拥有分类/视频独立购买记录 -> 下发视频但限制 8% 试看`。
  - **试看防盗**：仅前端限制 8% 是不够的，下发视频链接时必须进行 URL 鉴权/时效签名，防止用户抓包直连播放。

## 3. 多语言强规范（UniApp 核心）
本规范继承并严格执行 `uni-i18n-display-unification`。
- **后端模型层设计**：单词解释、分类名称、视频字幕翻译等需多语言展示的字段，数据库中采用 JSON 格式存储，例如 `{"zh": "苹果", "en": "Apple"}`。
- **后端接口层拦截**：后端下发给 Uni 用户的文本，必须通过 Service 层捕获请求头中的 `Accept-Language` 或前端传来的 `locale`，筛选出当前语种对应的文本后再下发（或直接下发，在前端用 `localText` 解析）。绝不允许在非多语言返回场景直接输出 JSON 导致前端乱码。
- **提示语多语言**：业务代码中如 `暂无视频片段`、`您还没有开通会员`，必须存在于前端 i18n 词库或由后端根据客户端语种转换后通过 `error` 抛出，禁止硬编码中文。

## 4. 重点功能实现基准与避坑指南

### A. 单词跟打（Typing）与交互
- **抛弃系统输入法**：跟打页面的英文输入**必须由前端绘制自定义 26 键盘**，拦截手机内置输入法的拼写检查、中文切换和首字母联想，确保监听的输入绝对准确且可控。
- **错词本自动记录**：在跟打过程中打错任何一个字母被判定为“红字重来”时，该单词应自动标记并加入 `english_word_error_log` 错题本。

### B. 视频双语与重点词高亮
- **外挂字幕处理机制**：不在 `video` 组件内混排。用独立的 `scroll-view` 渲染字幕流，根据视频 `@timeupdate` 与字幕数组的 startTime/endTime 时间轴进行匹配和联动。
- **词汇高亮后台清洗化**：**严禁在前端拿整句字幕通过正则实时去查询海量单词库。** 在后台录入字幕（或关联视频）时，必须执行预处理脚本——找出包含在 `english_word` 表中的重点词条，打上特定标签（如 `<w id="101">destiny</w>`），前端只需渲染此结构即可实现点击弹窗。

### C. 资源与句库收藏
- **关系映射**：用户的收藏行为（收藏单词、收藏双语字幕句子、收藏视频）必须采用关联表结构（如 `user_collect (user_id, target_type, target_id)`），绝对禁止在收藏表拷贝/冗余具体的单词拼写和字幕翻译原文，保证内容溯源的一致性。
- **免费音视频生成**：后台通过 Edge TTS 或对接优质离线/免费 API，在录入英文单句时自动生成 MP3 音频上传至 OSS 存储。

## 5. 项目落地流程指引
1. 第一阶段规划后端 Model，建表并配置好 Router 与 API 的多语言中间件。
2. 搭建后端清洗脚本与同步查询功能。
3. 提供基础接口给前端。
4. 前端落地自定义键盘、视频外挂滚动视图组件与双语组件。
