# Uni 多语言展示手工回归清单

## 适用范围
- SKU 规格展示
- 商品标签 nameI18n
- 配置类文案（payment methods、announcement_content、tryon config）

## 测试前置
1. 账号可登录，且有可查看的商品与 SKU 数据。
2. 准备两组样本：
- 组 A：字段为多语言对象或 JSON 字符串。
- 组 B：字段为 i18n key（例如 `color`、`red`）。
3. 确认当前版本已接入 `useI18nDisplay`。

## 核心路径回归（中文 -> 英文 -> 中文）

### 1. 商品详情 SKU 弹层
1. 进入商品详情页，打开 SKU 选择弹层。
2. 语言设为中文，记录规格名与规格值显示。
3. 不离开页面，切到英文。
4. 检查规格名/规格值是否同步切到英文，不出现中文残留或 key 原文。
5. 再切回中文，确认能回到中文展示。

### 2. 结算/订单摘要页
1. 进入支付页或订单确认页。
2. 检查商品名、规格摘要、支付方式名称。
3. 在页面停留状态切换语言。
4. 验证页面文案即时更新，不需刷新或重进。

### 3. 配置类页面
1. 进入使用公告、支付方式、试衣配置文案的页面。
2. 确认调用接口是否传 `includeI18n: true`（按页面设计要求）。
3. 切换语言后，确认公告与支付文案即时变化。

## 字段形态兼容检查
1. 多语言对象：`{"zh":"颜色","en":"Color"}`
2. JSON 字符串：`"{\"zh\":\"红色\",\"en\":\"Red\"}"`
3. i18n key：`"color"`、`"red"`
4. 纯文本：`"T-Shirt"`

预期：
- 对象/JSON：按当前语言显示。
- key：命中词条时翻译；未命中按策略回退。
- 纯文本：保持原文。

## 请求与返回校验
1. 抓包确认请求头包含：
- `Accept-Language`
- `X-Client-App: uni`
2. 抓包确认按策略携带 `includeI18n`：
- 默认单语页面：不带 `includeI18n`
- 页面内要实时切语的配置页面：带 `includeI18n=1`

## 失败判定
- 英文页面出现中文残留。
- 页面直接显示 key（如 `color`）且词条应存在。
- 切语后需刷新页面才更新。
- 同一字段在不同页面显示不一致。

## 提交前必做
1. 执行一次全量构建：`npm -C uni run build:h5`
2. 扫描确认页面层无 `resolveI18nDisplayText` 直调（仅允许在 `useI18nDisplay` 与 `utils/i18n.js` 内部出现）。
3. 在变更说明中附上测试路径与结果。
